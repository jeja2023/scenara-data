# 核心平台数据能力拆分与迁移

- **责任团队**：景枢数据团队
- **迁移提供方**：景枢核心平台（Core）
- **当前状态**：迁移计划已定义，等待生产环境执行

## 迁移顺序

1. 在契约仓库中固定目标领域模型、难例清单输入（`HardSampleManifest`）和数据集版本引用输出（`DatasetVersionReference`）。
2. 核心平台建立数据平台远程客户端（`DataPlatformClient`），现有本地实现作为具有明确退出条件的兼容适配器。
3. 建设数据平台独立数据库、对象存储、身份透传和审计回传链路。
4. 执行全量数据迁移，并核对数据集、版本、样本和标注的数量、哈希摘要与数据血缘。
5. 开展影子读流量对比，完成短时读写冻结或基于发件箱/变更数据捕获（Outbox/CDC）的增量同步。
6. 核心平台正式切换到远程数据平台客户端，原有本地数据表置为只读观察状态。
7. 回滚观察窗口结束后正式退役原有写路径，严禁长期保持双写。

## 执行方式

核心平台数据导出使用 [export_data_migration.py](/abs/path/D:/project/scenara/scripts/export_data_migration.py)，数据平台数据导入使用 [import_data_migration.py](/abs/path/D:/project/scenara-data/scripts/import_data_migration.py)。当前导入入口保持为离线命令行工具，避免暴露一个接收任意宿主机路径的 HTTP 导入接口；迁移包作用域、摘要、记录数和终态幂等都由导入器在本地逐项校验。

## 回滚策略

切换前保留核心平台原写路径和只读快照。发生数量不一致、摘要不匹配、权限异常、审计丢失或延迟超标时，立即停止增量消费，将核心平台路由恢复到旧适配器，并按事件游标记录待重放范围。不得在回滚时重编码业务 ID、修改状态枚举名或覆盖已发布版本。

退出回滚窗口前必须证明：版本标识保持不变、清单摘要一致或存在可验证映射、权限范围不扩大、审计记录完整可查且样本内容不可篡改。
