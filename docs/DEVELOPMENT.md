# 开发规范

模块按数据集（datasets）、版本（versions）、样本（samples）、标注（annotations）、质量（quality）和血缘（lineage）领域边界划分，严禁建立无清晰职责边界的通用工具目录（如 `utils`、`common` 或 `helpers`）。业务逻辑依赖仓储（Repository）、提供方（Provider）和客户端（Client）端口，适配器通过契约测试进行可替换性验证。

## 前端工作台规范

独立工作台位于 `frontend/data-console`，当前版本为 `0.1.9`。用户可见文本默认使用中文，以下内容保留原文以保证协议兼容性和排障准确性：API 路径、状态枚举、错误码、业务 ID、模型/流水线 ID、媒体类型、对象存储键和权限范围。新增页面或交互时应同时补充加载中、空数据、部分成功、请求失败和权限失败状态。

工作台使用本地用户名密码会话访问直连后端。默认用户名为 `admin`，默认密码复用 `SCENARA_DATA_TRUSTED_SERVICE_TOKEN`；如需与服务间令牌分离，设置 `SCENARA_DATA_CONSOLE_PASSWORD`。登录成功后前端只保存会话令牌和连接上下文，后续业务请求由后端会话令牌恢复租户、项目、主体、权限范围和产品授权。

前端列表请求必须遵守后端分页契约，最大分页限制 `limit` 为 `100`。探针请求和业务请求应独立处理，不能用任一业务接口的失败结果覆盖真实健康状态。涉及版本治理的按钮必须与后端状态机一致，并以接口返回的实际状态更新反馈文案。

涉及移动端的页面调整应检查 `390px` 宽度：顶部导航不能裁掉刷新、连接状态或设置入口；长地址、说明、摘要和 ID 必须截断或换行；表格可以横向滚动，但页面本身不得产生无意的横向溢出。

新增公共 API、事件、状态或错误码前必须先在契约仓库（`scenara-contracts`）登记。所有写操作必须定义权限、幂等、审计和失败处理路径。时间统一使用 UTC RFC 3339 格式，持续时间使用带单位字段，跨仓库文件使用 SHA-256 不可变对象引用。
